## 本章考情

每年 5~7 分，且**下午试题二（数据库设计：ER 图 + 关系模式）固定考**。上午高频：三级模式、ER 转关系模式、关系代数结果集、候选码与范式判定、SQL 空值/权限。

## 10.1 三级模式与两级映像

### 精讲

| 层 | 名称 | 面向 | 例子 |
|---|---|---|---|
| 外模式 | 子模式/用户视图 | 用户 | 视图 VIEW |
| 概念模式 | 模式 | 全体用户 | 基本表 |
| 内模式 | 存储模式 | 物理存储 | 索引、聚簇、存储结构 |

**两级映像**保证独立性：

- 外模式/模式映像 → **逻辑独立性**（表结构变了，应用程序不用改）
- 模式/内模式映像 → **物理独立性**（存储结构变了，模式不用改）

> 【例】"对表创建聚簇索引"改变的是**内模式**；"为 user 表建视图"是外模式；数据字典中保存的是视图的**定义**。

### 易错警示

- 聚簇索引/存储方式 → 内模式；视图/外模式；全局表结构 → 模式。

## 10.2 ER 模型与转换（下午必考）

### 精讲

**三种冲突**（分 ER 图集成时）：属性冲突（类型/取值范围不同，如"工号"一个是数字一个是字符）、命名冲突（同名异义、异名同义）、**结构冲突**（同一对象在不同局部图中抽象不同，实体 vs 属性——需**统一**）。

**转关系模式规则**：

- 实体 → 一个关系模式，属性=实体属性，码=实体码。
- **1:1 联系**：并入任意一端，加对方码。
- **1:n 联系**：并入 n 端，加 1 端的码。
- **m:n 联系**：**必须**转换成独立关系模式，码 = **两端实体码的组合**（联系自身属性作非主属性）。

**属性冲突 vs 结构冲突辨析**：同一实体在不同分图属性个数不同 → 结构冲突。

### 易错警示

- 只有 m:n 必须独立建模式；1:1 和 1:n 都可以合并进实体模式。
- 集成 ER 图时"职工/教师"若为同一实体对象，合并属性是消除**结构冲突**。

## 10.3 关系代数

### 精讲

五种基本运算：选择 σ（行）、投影 π（列、**自动去重**）、并/差、笛卡尔积 ×；导出运算：交、连接 ⋈、除 ÷。

**自然连接**（考最多）：按**同名属性等值**连接并**去掉重复列**。列数 = R列数 + S列数 − 公共属性数。

> 【例】R(A,B,C) 3 列，S(A,D) 2 列，公共属性 A → 自然连接 3+2−1 = **4 列**。

**外连接**：左外 = 左表全保留（不匹配补 NULL）；右外、全外同理。元组数计算题按"匹配行 + 未匹配保留行"数。

**除法**：R ÷ S = 在 R 中找出"与 S 全部元素都关联"的元组的剩余属性值。

选择投影综合题写法：σ3='销售部1'(E)（第 3 列等于该值，字符串加引号、关系写在括号外）；组合时"先选择后投影再连接"。

### 易错警示

- 投影自动去重；选择对行、投影对列，别写反下标。
- 自然连接结果列数公式一定要减公共属性。

## 10.4 SQL

### 精讲

```sql
SELECT 姓名, AVG(薪资) FROM T
WHERE 部门 <> '行政'          -- 分组前过滤（不能用聚合函数）
GROUP BY 姓名
HAVING AVG(薪资) > 5000      -- 分组后过滤（可用聚合函数）
ORDER BY AVG(薪资) DESC;     -- 排序，DESC 降序
```

- **WHERE 不能用聚合函数，HAVING 才行**——年年考。
- 嵌套查询：`IN`、`EXISTS`（相关子查询，外层一行验一次）、`ANY/ALL`。
- 视图：`CREATE VIEW v1 AS SELECT...`，视图是**虚表**，数据字典只存定义；更新受限（含 GROUP BY/DISTINCT 的视图不可更新）。
- 权限：`GRANT SELECT ON 表 TO 用户 WITH GRANT OPTION`（可转授）；`REVOKE` 收回。
- 空值：`NULL` 判断用 `IS NULL`；`count(*)` 计所有行，`count(列)` 不计 NULL；NULL 参与算术结果为 NULL。

### 易错警示

- EXISTS 是"存在即取"，通常写 `SELECT *`；相关子查询执行次数 = 外层行数。

## 10.5 函数依赖与范式（必考计算）

### 精讲

**求候选码**：只在 F 左边出现过的属性必在候选码中；两边都没出现的一般也在码中。用闭包验证：$X^+$ = 从 X 出发能推出的全部属性，覆盖 U 则 X 是超码；极小化后得候选码。

**传递依赖**：若 X→Y，Y→X 不成立，Y→Z，则 X **传递**→ Z。冗余依赖：能被其他依赖推出的（如 A→H 且 A→B→DH）。

**范式判定流程**：

1. 1NF：属性原子（关系数据库默认满足）。
2. 2NF：消除**非主属性对码的部分依赖**（码是复合属性时才可能出现）。
3. 3NF：消除**传递依赖**。
4. BCNF：所有依赖的决定因素都含码。

> 【例】R(教师号，姓名，部门号，岗位，联系地址，薪资)，F：教师号→(姓名,部门号,岗位,联系地址)，岗位→薪资。
> 候选码 = 教师号（单属性 → 无部分依赖，满足 2NF）；教师号→岗位→薪资是传递依赖 → **最高 2NF**，存在冗余与插入/删除异常。

### 易错警示

- 候选码是单属性时不存在部分函数依赖，直接看传递依赖定 2NF/3NF。
- "存在冗余"与"存在传递依赖"常同时出现在正确选项里。

## 10.6 事务与并发控制

### 精讲

**ACID**：原子性、一致性、隔离性、持久性。由**事务管理/DBMS 的恢复与并发控制机制**保证。

**并发三大问题**：丢失修改、读脏数据（读了未提交的回滚数据）、不可重复读。

**锁协议**：

| | X 锁（排他写） | S 锁（共享读） |
|---|---|---|
| X 锁 | ✗ | ✗ |
| S 锁 | ✗ | ✔ |

- 一级封锁：修改前加 X 锁直到结束——防丢失修改。
- 二级：+ 读时加 S 锁（读完即放）——防脏读。
- 三级：S 锁到事务结束——防不可重复读。
- **两段锁协议（2PL）**：先扩后缩，保证**可串行化**，但不能避免死锁。

**故障与恢复**：

| 故障 | 例子 | 恢复手段 |
|---|---|---|
| 事务故障 | 除零、逻辑错 | 撤销（UNDO） |
| 系统故障 | 断电、宕机 | 重启时 UNDO 未提交 + REDO 已提交 |
| 介质故障 | 磁盘损坏 | 备份 + 日志重做 |

检查点技术加速恢复；**日志先写原则**。

### 易错警示

- 两段锁：可串行化 ✓、死锁 ✗（不预防）。
- 系统故障"内存数据丢失、外存完好"——REDO 已提交、UNDO 未提交。

## 10.7 分布式数据库与其他

- **分片透明性**级别最高（用户不知道分片）；其次位置透明、局部映像透明。分片方式：水平、垂直、混合。
- "某场地故障可用其他场地副本" = **可用性**好。
- 数据仓库：面向主题、集成的、相对稳定、反映历史变化；OLAP 多维分析 vs OLTP 事务。
- 反规范化：适当冗余换取查询性能（增加派生列、合并表）。
