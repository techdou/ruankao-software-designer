## 本章考情

上午卷 8~11 分，**分值最大章**；下午卷的软件分析设计题也扎根于此。过程模型选型、内聚耦合、测试覆盖、关键路径是四个年年考的支柱。

## 6.1 开发过程模型（必考选型）

### 精讲

| 模型 | 核心特征 | 适用场景 | 常考"不正确" |
|---|---|---|---|
| 瀑布 | 线性顺序、文档驱动、**阶段评审** | 需求明确稳定 | 缺乏灵活性 |
| 原型（快速原型） | 先做可运行原型摸清需求 | **需求不明确** | 不适用于大型系统 |
| 增量 | 分批交付可用增量 | 需求可分段 | 配置管理复杂、管理成本高 |
| 螺旋 | 瀑布 + **风险分析**，迭代 | 大型、高风险项目 | 要求风险分析能力、成本高、迭代多会延期 |
| 喷泉 | **面向对象**、迭代无间隙 | OO 开发 | — |
| RUP | 用例驱动、以架构为中心、迭代；四阶段（初始/精化/构建/转换） | 大中型 | — |
| 敏捷（Scrum/XP） | 拥抱变化、短迭代、人重于过程 | 需求多变、小团队 | — |
| AUP | UP 的敏捷版：大型任务连续、小型活动迭代 | — | 每个系统需要完全不同的策略（错） |

> 【例】"快速提供一个初始版本让用户测试"——是**原型/增量**的特点，说成螺旋模型就错。

### 易错警示

- 螺旋模型两连选的"不正确"项常是"开发成本低""快速提供初始版本"。
- 原型模型"加速开发、节约成本"是优点说法，但**不适用大型系统**。

## 6.2 需求工程与质量特性

### 精讲

**需求分类**：功能需求 / 非功能需求（性能、安全、可用性）/ 设计约束。需求开发 = 获取 → 分析 → 定义（规格说明 SRS）→ 验证；需求管理 = 变更控制、跟踪、基线。

**McCall 质量模型三方面**：运行（正确性、可靠性、易用性、完整性、效率）、修改（可维护性、灵活性、可测试性）、转移（可移植性、复用性）。

**ISO/IEC 25010（9126）**：功能性、可靠性、易用性、效率、**可维护性**、**可移植性**（+兼容性、安全性、使用质量）。

- 可维护性子特性：易分析、易修改、稳定性、易测试、遵循性。
- 可移植性子特性：**适应性、易安装性、遵循性、易替换性**（易测试性不属于！）。
- 效率 = 时间特性 + 资源特性；"每分钟处理请求数" = **吞吐量**。

### 易错警示

- 子特性归类题：先背"可维护性有易测试性，可移植性没有"。

## 6.3 模块设计与内聚耦合（必考排序）

### 精讲

**耦合**（模块间联系，从低到高）：

**数据 < 标记 < 控制 < 外部 < 公共 < 内容**

- 数据耦合：传简单参数。
- 标记耦合：传**数据结构**。
- 控制耦合：传**开关/标志**控制对方逻辑。
- 外部耦合：依赖外部环境/设备格式。
- 公共耦合：共享**全局数据/公共数据环境**。
- 内容耦合：**进入对方内部 / 代码重叠 / 多入口**——必须避免。

**内聚**（模块内联系，从低到高）：

**偶然 < 逻辑 < 时间 < 过程 < 通信 < 顺序 < 功能**

- 偶然：凑巧放一起（如杂项工具）。
- 逻辑：同类功能选一执行（所有输入输出处理）。
- 时间：同一时段执行（初始化模块）。
- 过程：按固定流程执行。
- **通信**：在**同一数据结构**上操作、产生同一输出。
- 顺序：前一个的输出是后一个的输入。
- 功能：单一完整功能——目标。

**启发式规则**：高内聚低耦合；**作用范围 ⊆ 控制范围**；扇入扇出适中（顶层高扇出、底层高扇入）；模块规模适中（**不是越小越好**）。

### 易错警示

- "通过外部变量交换信息"= 公共耦合；"传结构体"= 标记耦合；"传布尔标志"= 控制耦合。
- 通信内聚的标志句"都在同一数据结构上操作"。

## 6.4 测试（必考）

### 精讲

**阶段**：单元（模块，白盒为主，查内部逻辑）→ 集成（接口，自顶向下/自底向上/三明治）→ 系统（性能、安全、恢复等）→ 验收（用户参与，α 在开发方、β 在用户方）。**系统测试目标来自需求分析阶段**。

**白盒**（结构测试）覆盖强度从弱到强：

**语句 < 判定 < 条件 < 判定/条件 < 条件组合 < 路径**

- 语句覆盖最弱；路径覆盖最强。
- **McCabe 环形复杂度 $V(G) = E - N + 2$ = 判定结点数 + 1 = 封闭区域数**；基本路径测试用例数 = V(G)。

**黑盒**（功能测试）：等价类划分、**边界值分析**（取 3499/3500/3501 测"≤3500 免税"）、因果图、错误推测。

**调试**不是测试：测试是发现错误，调试是定位并改正。

### 易错警示

- V(G) 的三种算法结果一致；含复合条件的判定结点在"判定结点+1"法中算 1 个。
- "逻辑覆盖最强的是路径覆盖"，语句覆盖"不一定能发现所有判定错误"。

## 6.5 软件维护

### 精讲

| 类型 | 场景 | 占比 |
|---|---|---|
| **改正性** | 修 bug | ~20% |
| **适应性** | 适应环境/平台变化 | ~25% |
| **完善性** | 加功能、提性能 | **~50% 最大** |
| 预防性 | 为未来改造打基础 | ~5% |

> 【例】"修改索引方法使用户更快得到结果" = 完善性；"操作系统升级后重编译适配" = 适应性。

### 易错警示

- 占比最大的是**完善性**维护，不是改正性。

## 6.6 项目管理

### 精讲

**进度管理**：甘特图（直观，看不出依赖）、PERT 图（网状，看依赖与关键路径）。

**关键路径**：活动图中耗时最长的路径 = 项目最短工期；关键活动延迟一天工期延迟一天。求法：找出起点到终点所有路径取最大。

**风险管理**：识别 → 估计（概率×影响）→ 评价 → 应对（回避、转移、减轻、接受）；风险是"可能带来损失的事件"，**预测到也不能完全避免**；不能同时管理所有风险，要分级。

**配置管理**：基线（已通过评审的规格/产品）、版本控制、变更控制委员会（CCB）。

**CMM 五级**：初始 → 可重复 → 已定义 → 已管理 → **优化**；CMMI 阶段式同构。

**成本估算**：COCOMO II 三阶段（应用组装=对象点、早期设计=功能点、体系结构后=代码行）。

### 易错警示

- 关键路径题先数清所有路径；图缺失时按"最长加权和"算。
- 风险应对里"买保险"是**转移**。

## 考前速记

| 考点 | 一句话 |
|---|---|
| 螺旋模型 | 瀑布 + 风险分析，适合大型高风险 |
| 原型 | 需求不明确用它；不适用大型系统 |
| 耦合 | 数据标记控制外公共内容（低→高） |

| 作用范围 | ⊆ 控制范围 |

| 覆盖强度 | 语句最弱、路径最强 |
| 维护占比 | 完善性最大 |
| 关键路径 | 最长路径 = 工期 |
| CMM 五级 | 初可定管优 |
