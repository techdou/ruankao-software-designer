## 本章考情

每年 4~5 分。**算法归类（对称/非对称/摘要）和数字签名流程**是铁打的考点；攻击识别（DoS/SQL注入/XSS）、WAF/防火墙层次近年常考。纯记忆章，性价比高。

## 12.1 密码学基础（必考归类）

### 精讲

| 类别 | 算法 | 特点 |
|---|---|---|
| **对称**（私钥） | **DES、3DES、AES、RC4、IDEA、SM1/SM4** | 加解密同钥；快；**密钥分发难**（n 人需 n(n−1)/2 个密钥） |
| **非对称**（公钥） | **RSA、ECC、ElGamal、DSA、SM2** | 公钥加密私钥解；慢；解决**密钥分发**与**数字签名** |
| **报文摘要** | **MD5、SHA-1/256、SM3** | 单向散列、**不可逆**，保证**完整性** |
| 国密 | SM2（非对称/ECC）、SM3（摘要）、SM4（对称） | — |

**混合加密（数字信封）**：用对称密钥加密大数据 → 用对方公钥加密对称密钥 → 一起发送（性能 + 密钥分发兼得）。

> 【例】"为 IP 数据报加密"用 IPSec（网络层）；X.509 证书推荐 **RSA**；SM2 基于 **ECC**。

### 易错警示

- MD5/SHA 是摘要不是加密，"不可逆"；别归入对称/非对称。
- 对称密钥数量公式 n(n−1)/2，考点是"分发难"。

## 12.2 数字签名与 PKI（必考流程）

### 精讲

**数字签名**（验证身份 + 不可抵赖 + 完整性）：

1. 发送方对报文做**摘要**（MD5/SHA）。
2. 用**自己的私钥**加密摘要 → 签名。
3. 接收方用**发送方的公钥**解密签名得摘要 A。
4. 对收到的报文重新计算摘要 B，比对 A=B → 完整 + 确认来源。

**背熟一句话：私钥签名、公钥验证。**

- 保密性额外用"接收方公钥加密数据"——签名用自己私钥、加密用对方公钥，两者别混。
- **数字证书**（X.509）：CA 用自己私钥签发，绑定"公钥 ↔ 身份"；验证时用 **CA 的公钥**验证证书。
- PKI 组成：CA（签发）、RA（审核）、证书库、CRL（吊销列表）。

### 易错警示

- "用接收方公钥签名"是错的——签名永远用**发送方自己的私钥**。
- 验证证书用 CA 公钥，不是发送方公钥。

## 12.3 认证与访问控制

- 认证方式安全性：**口令 < U 盾/动态令牌 < 生物特征**；多因子 = 两种以上组合更安全。
- 访问控制任务：**保证资源不被非法使用和访问**；三要素：主体、客体、访问策略。DAC（自主）、MAC（强制）、RBAC（基于角色，便于授权管理）。
- 防火墙分类：

| 类型 | 层次 | 特点 |
|---|---|---|
| 包过滤 | 网络层（传输层） | 查 IP/端口，快、粗 |
| 应用网关（代理） | 应用层 | 查内容，细、慢 |
| 状态检测 | 跟踪连接状态 | 折中 |

- **WAF（Web 应用防火墙）**：专防网页篡改、SQL 注入、XSS 等 Web 攻击——"首页被篡改"选它。
- IDS 入侵检测：**报警不阻断**（旁路）；IPS：在线阻断。漏洞扫描：**只发现不修复**。

## 12.4 网络攻击识别（必考）

| 攻击 | 特征 |
|---|---|
| **DoS/DDoS** | 让目标**不能提供服务**（SYN Flood、Ping of Death） |
| 重放 | 截获合法通信**再次发送**（防：时间戳/一次性令牌） |
| 中间人 | 攻击者冒充双方转发并篡改 |
| **SQL 注入** | 构造恶意 SQL 获得数据库权限（防：**参数化查询/预编译**、过滤、最小权限） |
| **XSS 跨站脚本** | 向页面注入恶意脚本窃取 Cookie（防：输出编码） |
| 钓鱼 | 仿冒站点骗信息 |
| 会话劫持 | 窃取 SessionID |

**安全属性**：机密性（加密）、**完整性**（未授权不能改变——摘要/签名）、可用性（DoS 破坏的就是它）、不可抵赖性（数字签名）、可控性、可审查性。

### 易错警示

- "不能继续提供服务" = DoS；"窃取用户口令" = XSS/钓鱼；"获得数据库权限" = SQL 注入。

## 12.5 恶意代码与安全协议

- **病毒**：寄生于宿主程序，**需要宿主**；**蠕虫**：独立传播、利用漏洞自我复制；**木马**：伪装潜伏、远程控制（C/S）；逻辑炸弹：条件触发；勒索软件：加密文件勒索。
- 防治：**安装并及时升级防病毒软件**最有效；防火墙/IDS 防的是网络攻击不是病毒；备份是补救。
- 安全协议：**HTTPS = HTTP + SSL/TLS**（443，电子支付必须）；IPSec（网络层）、PGP（邮件）、SET（支付）、Kerberos（认证票据）。
