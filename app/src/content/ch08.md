## 8.1 面向对象基础

### 精讲

**三大特性**：封装（信息隐藏）、继承（一般-特殊，复用）、多态（同一消息不同响应）。

- **重载（overload）**：同类、同名、**参数不同**，**编译期**确定（静态绑定/早绑定）。
- **覆盖/重写（override）**：父子类、同名同参，**运行期**确定（动态绑定/晚绑定）。
- 多态的表现：父类引用指向子类对象，调用被子类覆盖的方法执行子类实现。
- 子类对象**可以**看作父类对象（向上转型）；父类对象**不能**看作子类对象。
- **this** 区分同名对象属性与局部变量；super 调父类。

**OOA（分析）活动顺序**：认定对象 → 组织对象 → 描述对象间相互作用 → 确定对象的操作。认定对象：把自然存在的**名词**作为候选。

**OOD（设计）活动**：识别类及对象、定义属性、定义服务、识别关系（含包）。

> 【例】"修改某个类的原因有且只有一个"= 单一责任；"不应强迫客户依赖其不使用的方法"= 接口分离；"重用包中一个类就要重用全部类"= 共同重用；"包依赖图中不允许环"= 无环依赖；"对一个包的变化影响其中所有类"= 共同封闭。

## 8.2 UML 图（必考识别）

### 精讲

**静态图（结构图）**：类图、对象图、构件图、部署图、包图、组合结构图、制品图。
**动态图（行为图）**：用例图、活动图、状态机图、顺序图、通信图、定时图、交互概览图。

| 图 | 建模对象 | 关键词 |
|---|---|---|
| 用例图 | 系统提供的**外部可见服务** | 参与者、用例、include/extend |
| 类图 | 类的静态结构 | 六种关系 |
| 对象图 | **某一时刻**一组对象及关系 | 类图的实例快照 |
| 构件图 | 构件的组织与依赖 | 静态**实现**视图 |
| 部署图 | 软硬件物理映射 | 节点 |
| 活动图 | **活动到活动的流程** | 分岔/汇合（并行）、分支（条件） |
| 状态机图 | **反应型对象**的状态变化 | 事件触发、entry/do/exit、when()=变更事件、after()=时间事件 |
| 顺序图 | 按时间顺序的消息交互 | 生命线、激活条 |

**类图六种关系**（箭头方向 + 强弱）：

```
泛化（实线空心三角，子→父）＝ 实现（虚线空心三角，类→接口）
> 组合（实心菱形，整体端）
> 聚合（空心菱形，整体端）
> 关联（实线）
> 依赖（虚线箭头）
```

- **组合**：整体灭则部分灭（人—心脏），同生共死。
- **聚合**：整体-部分但可独立存在（汽车—轮胎）。
- **依赖**：最弱，"使用"一下（参数、局部变量）。

状态图细节：动作可在状态内（entry/do/exit）也可在转换时执行；转换未指定监护条件时事件发生即离开当前状态（终止 do）；when(b=5) 是**变更事件**，after(5s) 才是时间事件。

### 易错警示

- 菱形指向**整体**（整体端画菱形）。
- "状态图对……建模"选**反应型对象**；活动图对**流程**建模。

## 8.3 设计模式（必背 23 个）

### 精讲

**三大类**：创建型 5、结构型 7、行为型 11。

**创建型**（怎么 new）：

| 模式 | 一句话意图 |
|---|---|
| 单例 Singleton | 一个类**仅一个实例**，全局访问点 |
| 工厂方法 Factory Method | 定义创建对象接口，**子类决定实例化哪个类** |
| 抽象工厂 Abstract Factory | 创建**一族**相关对象而无需指定具体类 |
| 生成器 Builder | 分步构建复杂对象，**同样的构建过程创建不同表示** |
| 原型 Prototype | **克隆**已有实例来创建新对象 |

**结构型**（怎么组合成大结构）：

| 模式 | 一句话意图 |
|---|---|
| 适配器 Adapter | 转换接口，让**不兼容类**协同工作 |
| 桥接 Bridge | **分离抽象与实现**，使二者独立变化 |
| 组合 Composite | **树形**结构表示"部分-整体"，一致对待单个与组合对象 |
| 装饰器 Decorator | **动态**给对象**添加职责**，比继承灵活 |
| 外观 Facade | 为子系统提供**统一的高层接口** |
| 享元 Flyweight | **共享**大量细粒度对象，节省内存 |
| 代理 Proxy | 控制对原对象的**访问**（远程/虚拟/保护代理） |

**行为型**（怎么交互分工）：

| 模式 | 一句话意图 |
|---|---|
| 责任链 Chain of Req. | 请求沿处理者链传递；**处理对象集合动态指定** |
| 命令 Command | **将请求封装为对象**，参数化客户、可撤销 |
| 解释器 Interpreter | 给定语言，定义其文法的**表示与解释器**（抽象语法树） |
| 迭代器 Iterator | 顺序访问聚合对象**而不暴露内部表示** |
| 中介者 Mediator | 用中介封装**一系列对象交互**，使对象不必显式引用 |
| 备忘录 Memento | 在不破坏封装下**保存并恢复对象状态** |
| 观察者 Observer | **一对多通知**；对象状态变化自动通知依赖者 |
| 状态 State | 行为随**内部状态**改变，运行时切换行为 |
| 策略 Strategy | 定义**算法族**，可互相替换（打折/返利/满减） |
| 模板方法 Template | 定义算法骨架，**子类重定义某些步骤** |
| 访问者 Visitor | 在**不改元素类**的前提下定义作用于元素的新操作 |

**识别口诀**（题干关键词 → 模式）：

- "封装请求为对象"→ 命令；"通知所有依赖者"→ 观察者；"算法族切换"→ 策略
- "状态改变行为"→ 状态；"链式处理/级别过滤"→ 责任链；"统一接口屏蔽差异"→ 适配器
- "同一过程不同表示"→ 生成器；"克隆"→ 原型；"树形部分整体"→ 组合
- "分步构造"→ 生成器 vs "分离抽象实现"→ 桥接 vs "动态加职责"→ 装饰器

**下午题套路**（Java 代码填空）：给类图填空。先看抽象类/接口中声明了什么方法，再看子类实现了什么——空格几乎都是"父类引用持有子类对象""调用抽象方法""注册观察者"这三类。

### 易错警示

- 状态 vs 策略结构像：状态是"内部状态自己切换行为"，策略是"外部注入算法"。
- 桥接 vs 装饰器：桥接分离两个变化维度，装饰器叠加职责。
- 适配器"转换已有接口"，外观"简化复杂子系统"——别混。
