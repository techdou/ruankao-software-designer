## 本章考情

上午 2~4 分，但**下午试题一（数据流图）是固定题型**——分层数据流图的补充（找缺失的外部实体/数据存储/数据流）是每年必考动作。上午题集中在 DFD 元素与绘制原则。

## 7.1 结构化分析：DFD 数据流图

### 精讲

**四种元素**（下午题常让你"找缺失元素"）：

| 元素 | 图形 | 说明 |
|---|---|---|
| 外部实体 | 矩形（方框） | 系统之外的人/组织/系统，数据源或终点 |
| 加工（处理） | 圆或圆角矩形 | 数据变换，应有编号与名字 |
| 数据存储 | 双横线/开口矩形 | 静态保存，如"订单文件 D1" |
| 数据流 | 带名箭头 | 只能是**数据**，不是控制流 |

**绘制原则**：

1. 对每个数据流/加工/存储/外部实体**都要命名**（名字用名词性短语）。
2. **父图与子图平衡**：父图某加工的输入输出数据流 = 其子图与外界的输入输出流。
3. 子图加工编号 = 父图加工号. 序号（1 → 1.1、1.2）。
4. 一个加工的输入输出**不宜过多**；分解要**均匀**。
5. **只画数据流，不画控制流**；加工之间不能只有无名字的连线。
6. 数据存储与外部实体之间**不能直接**有数据流（必须经过加工）。

**数据字典**：定义数据流图中**每个元素**。加工逻辑描述"做什么"，用**结构化语言、判定表、判定树**表示；**不写**具体数据结构与算法实现。

> 【例】多条件组合决定不同行为（客户类型×金额×信用）→ 用**判定表**最合适；"__属于/不属于加工逻辑的表述"→ "必须实现算法"错。

### 易错警示

- "DFD 中要表示出控制流"是错误的——那是流程图的事。
- 外部实体之间、数据存储之间不能直接拉数据流。

## 7.2 结构化设计：结构图与模块

### 精讲

**结构化设计（SD）**：面向数据流的设计，把 DFD 映射成**结构图（SC）**。

- **变换分析**：DFD 呈"输入→变换中心→输出"三段 → 映射为三大分支。
- **事务分析**：某加工按类型分派多个动作路径（事务中心）→ 每条路径一个模块。

**结构化程序设计**：仅用**顺序、选择（分支）、循环**三种基本结构，单入口单出口。

**模块设计七启发式**（与 ch06 呼应）：模块独立性（高内聚低耦合）、作用范围⊆控制范围、扇入扇出适度、规模适中、消除重复功能、避免病态连接（内容耦合）、功能可预测（不出现"存储垃圾"）。

### 易错警示

- "变换型"和"事务型"的判别：看 DFD 中间是**同一批变换**还是**按类型分流**。

## 考前速记

| 考点 | 一句话 |
|---|---|
| DFD 四元素 | 外部实体、加工、数据存储、数据流 |
| 父图子图 | 输入输出必须平衡 |
| DFD 没有什么 | 控制流 |
| 存储与实体 | 不能直接相连 |
| 加工逻辑 | 只写"做什么"：结构化语言/判定表/判定树 |
| 多条件组合 | 判定表 |
| SD 映射 | 变换分析 / 事务分析 |
| 三种基本结构 | 顺序、选择、循环 |
